# Лендинг Юлии Ребровой

Адаптивный сайт художницы-портретиста, отдельная витрина и защищённая панель управления. Node.js-сервер обслуживает сайт и API, PostgreSQL хранит контент, заявки, согласия и обезличенные события аналитики.

Шрифты Prata, Old Standard TT и Golos Text хранятся локально в `assets/fonts/` и распространяются по лицензии SIL Open Font License (тексты лицензий лежат рядом с файлами шрифтов).

## Локальный запуск

Для защищённой панели запускайте проект через Node.js 22+:

```powershell
node server.mjs
```

Откройте `http://localhost:4173`. Без `DATABASE_URL` публичные страницы используют встроенный контент, а серверные формы и синхронизация админки остаются отключены — персональные данные не сохраняются в Git или браузере.

Отдельная витрина готовых работ доступна по адресу `http://localhost:4173/shop.html`. Магазин не является блоком лендинга: у него собственные hero, каталог, фильтры, сценарий покупки и SEO-описание. Контент витрины берётся из общей панели управления.

## Панель управления

Панель мастерской доступна по адресу `http://localhost:4173/admin`. Прямой запрос к `admin.html` без действующей сессии также перенаправляется на вход.

- **Портфолио:** добавление и редактирование работ, описаний, категорий и изображений.
- **Магазин:** готовые товары, цены, размеры, статусы «в наличии / резерв / продано» и публикация на отдельном сайте-витрине `shop.html`.
- **Обращения:** заявки на портреты, сертификаты и готовые работы с простыми рабочими статусами.
- **Аналитика:** уникальные посетители, просмотры, целевые действия, обращения, конверсия и интерес к магазину — только после согласия посетителя.
- **Резервная копия:** экспорт и восстановление портфолио и магазина в JSON. Заявки намеренно не выгружаются открытым файлом.

### Настройка защищённого входа

Авторизация двухэтапная: разрешённый email и пароль проверяются на сервере, затем на этот же адрес отправляется шестизначный одноразовый код. После подтверждения сервер создаёт закрытую `HttpOnly`-сессию на 8 часов. Пароль, почтовый ключ и секреты сессий не попадают во frontend или Git.

1. В Яндекс ID создайте отдельный **пароль приложения** типа «Почта». Обычный пароль от почтового ящика использовать нельзя.
2. В терминале из папки проекта запустите интерактивную настройку:

   ```powershell
   node scripts/setup-auth.mjs
   ```

   Команда запросит единственный разрешённый email, пароль панели и пароль приложения Яндекс Почты. Секретные поля не отображаются. Настройки сохраняются в локальном `.env`, который исключён из Git.

3. Запустите сервер: `node server.mjs`.

Для production установите `NODE_ENV="production"`, используйте HTTPS и передайте те же переменные окружения через панель хостинга. SMTP по умолчанию настроен на защищённое соединение с `smtp.yandex.ru:465`.

## База данных

1. Создайте управляемую PostgreSQL в российском регионе Timeweb Cloud.
2. Скопируйте `.env.example` в локальный `.env` либо добавьте переменные в панели приложения. Не публикуйте `.env`.
3. Укажите `DATABASE_URL`, `PII_ENCRYPTION_KEY` и `EVIDENCE_HASH_SECRET`.
4. Примените схему: `npm run db:migrate`.
5. Запустите сервер. При первом входе админка автоматически перенесёт встроенные работы и товары в пустую базу.

Персональные поля заявок шифруются AES-256-GCM до записи в PostgreSQL. Согласия хранятся с версией документа и техническим доказательством без сохранения открытого IP-адреса. Команда `npm run db:cleanup` удаляет просроченную аналитику и обезличивает неактуальные обращения; в production её нужно запускать ежедневно планировщиком.

Загруженные через админку изображения в текущем MVP сохраняются как WebP внутри данных PostgreSQL. Это работает без отдельного файлового сервиса; при росте каталога следующий разумный шаг — перенести оригиналы в S3-совместимое хранилище Timeweb, оставив в базе только ссылки.

Полная инструкция развёртывания: [`TIMEWEB-DEPLOY.md`](TIMEWEB-DEPLOY.md).

## SEO и аналитика

- OG-превью: `assets/og/yulia-rebrova-og.png` (1200×630).
- JSON-LD в `index.html`: `WebSite`, `ProfilePage`, `Person`, `ProfessionalService`, `Service` и каталог предложений.
- Событийная модель в `site-insights.js`: CTA, заявка, сертификат, фильтры, мобильные карусели, интерес к магазину и глубина просмотра. Имена и текст заявки в аналитику не передаются.
- Чтобы включить Яндекс Метрику, укажите идентификатор в `yandex-metrika-id`. Провайдер загружается только после явного согласия. Google Analytics оставьте выключенным до отдельной оценки трансграничной передачи и уведомления Роскомнадзора.
- После выбора рабочего домена замените корневые значения `/` у `canonical`, `og:url` и URL в JSON-LD на абсолютный HTTPS-адрес. Тогда же добавьте абсолютный `sitemap.xml` в `robots.txt` и панели Google Search Console / Яндекс Вебмастер.

## Перед публикацией

1. Заполнить реквизиты оператора и исполнителя в правовых документах; до этого они намеренно помечены `noindex`.
2. Подать обязательные уведомления и выполнить пункты из [`legal/LEGAL-CHECKLIST-RU-2026.md`](legal/LEGAL-CHECKLIST-RU-2026.md).
3. Указать рабочий домен, абсолютные canonical/OG/JSON-LD URL и идентификатор разрешённой аналитики.
4. Дополнить оставшиеся карточки реальными работами и уточнить форматы/сроки у изображений с пометкой «Уточняется».
5. Проверить публичный URL, формы, мобильную версию, Schema.org Validator и Яндекс Вебмастер.
